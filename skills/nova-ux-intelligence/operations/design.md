# Design operations

Choose the operation that matches the requested outcome, not a full redesign ritual.

| Operation | Concrete result |
|---|---|
| EXPLORE | A few materially distinct directions with task fit, costs and validation need |
| DESIGN | Information and interaction structure, then visual expression and applicable states |
| REDESIGN | KEEP/FIX/IMPROVE/REMOVE/INTRODUCE map; change only justified scope |
| CLARIFY | Better labels, hierarchy or feedback resolving ambiguity |
| SIMPLIFY | Fewer unnecessary decisions/actions without hiding critical information |
| DISTILL | Essential content and signal retained while secondary detail moves appropriately |
| NORMALIZE | Consistent semantic tokens, components and behavior with justified exceptions |
| ADAPT | Context/device/locale/input transformation preserving task meaning |
| POLISH | Refined type, spacing, alignment and motion after lower-layer quality holds |

Start from the task and decision journey, then information priority → hierarchy → interaction → visual treatment. Preserve valuable structure, content, brand and components. Reuse existing tokens before proposing numbers. Distinguish an exact user constraint from a proposed means; challenge the means without quietly overriding the constraint.

Forms use PREVENT → GUIDE → ACCEPT FLEXIBLY → VALIDATE → EXPLAIN → RECOVER. Remove unnecessary fields, explain required inputs, accept reasonable formats, normalize safely, preserve entered data, associate errors accessibly and prevent duplicate consequential submissions. Interface locks support server-side protection; they do not replace it. See [interaction knowledge](../references/interaction.md).

For mobile commerce, decide information needs before CTA count. Evaluate whether a sticky action blocks content, focused fields, zoomed text or the software keyboard. Retain decision-critical price, suitability and terms. A clean screen that conceals these is not simpler for the user.

Example: users compare many exception records; rounded cards would break column comparison. Keep the table, improve exception emphasis and filters, reuse supported row tokens. This is a task-based recommendation, not a universal ban on cards. Verify comparison and keyboard actions after rendering.

Select materials through [Material Intelligence](../references/materials.md). Plan content/state boundaries before polishing; finish through [verify](verify.md) when producing an implemented artifact.
