# 13-domain knowledge router

Search/read only the rows and linked modules relevant to the task. Stable heuristics below are not universal requirements; retrieve current primary evidence when a consequential recommendation depends on it. This is a compact retrieval map, not a claim to embed complete research libraries.

| Domain | Decision focus and retrieval |
|---|---|
| 01 Human Factors & Cognitive Psychology | Connect actual recognition, attention, memory or choice burden to observed behavior; avoid principle name-dropping. See [evidence](evidence.md). |
| 02 User Research & Task Analysis | Identify participants, goals, constraints, task frequency and success signals; distinguish reported preference from observed task performance. |
| 03 Information Architecture | Organize for findability, comparison and decision sequence; test labels and grouping instead of equating fewer items with simplicity. |
| 04 Interaction Design | Affordance, feedback, control, focus, error prevention and recovery; see [interaction](interaction.md). |
| 05 Visual & UI Design | Hierarchy, type, alignment, rhythm, imagery and semantic color serve the task; Material Intelligence lives in [materials](materials.md). |
| 06 Content Design & UX Writing | Clear labels, action outcomes, honest conditions and useful error messages; preserve decision-critical content. |
| 07 Forms & Transactional UX | Minimize necessary collection, flexible formats, accessible errors, progress, recovery and duplicate protection; see [interaction](interaction.md). |
| 08 Responsive / Adaptive / Device / Internationalization | Input/device constraints, content expansion, semantic RTL and localized formats; see [adaptive](adaptive.md). |
| 09 Accessibility & Inclusive Design | Semantics, keyboard, names/roles/values, assistive technology, contrast, zoom and motion; use applicable W3C/platform standards and [verification](../operations/verify.md). |
| 10 Design Systems / Components / Tokens / Design-to-Code | Retrieve actual decisions and component capabilities; justify exceptions; compare delivered runtime with design. |
| 11 Product / Commerce / Conversion | Suitability, trust, transparent cost, informed action and downstream outcomes; see [design](../operations/design.md). |
| 12 Critique / Validation / QA | Evidence-based issue records, severity/confidence, task validation and executed-check records; see [diagnose](../operations/diagnose.md) and [verify](../operations/verify.md). |
| 13 Performance / Resilience / Failure States | Device bottlenecks, loading/offline/error boundaries, continuity and safe retry; see [verify](../operations/verify.md). |

Knowledge content, WCAG/platform updates, research, framework APIs, Figma features, CSS capabilities and material implementation techniques are dynamic. Keep project branding, pricing, channels, product structures and local operating rules in project context/design systems, outside this generic skill.
